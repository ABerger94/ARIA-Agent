## Compatibility and remaining validation

- File names for workspace reads/writes must be relative. An invalid path is rejected instead of silently changed; a missing nested file no longer falls back to a different basename.
- The default project's data paths remain compatible. Named-project mirror copies use `projects/<project-id>/` to avoid overwriting another project's database or chat log. Mirroring is asynchronous and best effort; completion of a primary save does not mean its queued mirror has already finished.
- A background job that outlives ARIA's process cannot be cancelled by trusting its old PID. Its process must be checked on the owning computer. This protects unrelated processes after PID reuse.
- Credential redaction applies to new diagnostic events. Historical logs have not been rewritten. Field/value redaction does not identify every possible secret embedded in arbitrary source code or prose.
- Other legacy tool handlers retain their current public result interfaces. Typed-result coverage should continue expanding as those handlers change; this patch tests the specific false-success paths above.
- Native Windows COM, the frozen installer, actual GUI automation, real Gemini Live audio, model credentials/quota, cameras, and robot hardware still need acceptance on their supported environment. The existing Windows CI job remains the validation route for the locked product build.
- The Chromium phone test is a collection skip in this environment because its native WebEngine import is unavailable. Phone authentication and approval API tests do run. The Windows-only suite is skipped on Linux; optional push/audio cases account for the other skips.
